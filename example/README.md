# Example corpus: Fennmore Commerce Center

A miniature, fully fictional wiki instance that exercises the whole system:
three records (an RFI, the PCO it triggered, and the amendment that executed
it), one topic page walking the change trail with epistemic-class tags, three
plain-text "originals" under `Originals/`, and a filled-in
`.claude/project-invariants.yaml`.

Everything here is invented: parties, people, record IDs, dollar figures.
The cast matches the examples used throughout `schemas/` and `docs/`. Any
resemblance to a real firm or person is coincidental.

## Run the validation suite against it

From the repository root:

```bash
scripts/validate.sh --root example --schemas schemas
```

Four steps run: index rebuild, cross-reference resolution, structural audit,
semantic audit. All four pass on the committed state. `index.md` and the
`referenced_by[]` arrays are machine-written by steps 1 and 2; edit records
and re-run rather than editing those by hand. Reports land in
`example/.claude/health/` (gitignored; regenerable).

## What to poke at

- Break a figure: change `priced_amount` in
  `records/pcos/PCO-217.md` to a value not present in its cited sidecar and
  re-run. The semantic audit fails with a `dollar_not_in_source` violation.
- Break structure: remove a required field or misquote a title containing
  `#`. The structural audit fails.
- Follow a pending-target: `PCO-217.md` references `Change-0455.md`, which
  does not exist yet. The resolver reports it as pending rather than broken;
  ingest such a record and the graph edge resolves itself.

## Note on the "originals"

In a real deployment, `Originals/` holds source PDFs with `.txt` sidecars
generated by `pdftotext -layout`. Here the originals are plain text so the
repository stays lightweight; each record cites the text file as both path
and sidecar.
